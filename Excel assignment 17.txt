Q.1 What are modules in VBA and describe in detail the importance of creating a module?
ANS:A module is the fundamental syntactic unit of VBA source code. The physical representation of a module is implementation 
    dependent but logically a VBA module is a sequence of Unicode characters that conform to the VBA language grammars.
	A module consists of two parts: a module header and a module body.


Q.2 What is Class Module and what is the difference between a Class Module and a Module?
ANS:Class Module:
    Purpose: Used to define the structure and behavior of a custom object (a class). 
    Content: Contains code for properties, methods (functions or subroutines), and events related to the object. 
    Instantiation: You can create instances (objects) of a class module using the New keyword. 
    Scope: Data within a class module exists separately for each instance of the class. 
    Example: A class module could define a "Customer" object with properties like name, address, and methods like "PlaceOrder". 

    Module (Standard Module):
    Purpose: A container for general code, procedures, and variables, but not for defining custom objects. 
    Content: Can hold functions, subroutines, constants, and variables that can be used by other modules or procedures. 
    Instantiation: Modules cannot be instantiated; they are not meant to create objects. 
    Scope: Data within a module exists for the duration of the application. 
    Example: A module could contain functions for performing common tasks, like calculating a discount or validating data. 



Q.3 What are Procedures? What is a Function Procedure and a Property Procedure?
ANS:In programming, a procedure is a named block of code that performs a specific task, while a function procedure returns a
    value, and a property procedure handles custom properties. 
    Procedures:
    Definition: A procedure is a named section of code that is executed as a unit, designed to perform a specific task. 
    Purpose: Procedures are used to organize code, make it reusable, and improve readability. 
    Types: In Visual Basic, procedures can be Sub procedures (which don't return a value) or Function procedures (which return 
	a value). 
    Function Procedures:
    Definition: A function procedure is a type of procedure that performs a task and returns a value to the calling code.
    Purpose: Function procedures are used when you need to calculate a result or retrieve information that can be used 
	elsewhere in your program.
    Property Procedures:
    Definition: Property procedures are used to create and manipulate custom properties for modules, classes, or structures.
    Purpose: They allow you to define how properties are accessed (read) and modified (written).
    Types: Property Get: Used to retrieve the value of a property.
    Property Let: Used to set the value of a property (for non-object variables).
    Property Set: Used to set the value of a property (for object variables).

Q.5 What is a sub procedure and what are all the parts of a sub procedure and when are they used?
ANS:A sub procedure is a block of code that performs a specific task, similar to a function, but it doesn't return a value.
    It's defined using Sub and End Sub statements, and it can take arguments for input and modify variables. 
    Parts of a Sub Procedure:
    Sub Statement: This initiates the sub procedure and defines its name and any arguments it takes. 
    Example: Sub MyProcedure(argument1 As Type, argument2 As Type) 
    Procedure Body: This is where the code to be executed resides, performing the desired actions. 
    End Sub Statement: This marks the end of the sub procedure. 
    Arguments: These are values passed into the sub procedure from the calling code, allowing for flexibility and reusability. 
    Local Variables: Variables declared within the sub procedure are only accessible within that procedure. 
    Optional Call Statement: While not always necessary, the Call statement can be used to explicitly call a sub procedure. 
    When are Sub Procedures Used?
    Code Organization: Sub procedures help break down complex tasks into smaller, manageable units, improving code readability and maintainability. 
    Reusability: They allow you to write code once and reuse it multiple times within a program or across different modules. 
    Modularity: Sub procedures promote modular programming, making it easier to test, debug, and modify individual components of a program. 
    Event Handling: Sub procedures can be used to handle events, such as button clicks or data changes in a user interface. 
    Data Manipulation: They can be used to perform operations on data, such as sorting, filtering, or transforming data. 
    Input/Output: Sub procedures can handle user input, display information, or interact with external devices.
